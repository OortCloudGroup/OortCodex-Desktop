## 修复：`irm <ps1> | iex` 报「赋值表达式无效」（用户实测报错）

- 根因链（实测复现，用 `[scriptblock]::Create()` 复现了完全相同的报错）：
  1. 静态站返回 `application/octet-stream` 且无 charset，**PowerShell 5.1 的 `irm` 按单字节解码**
     （返回 String，长度 = 字节数 7552，即 UTF-8 被当成 latin1）。
  2. 于是 **UTF-8 BOM 变成 3 个可见字符 `ï»¿`** 顶在 `param` 前面 → `param()` 不再是首条语句
     → 报「赋值表达式无效。赋值运算符输入必须是能够接受赋值的对象」（InvalidLeftHandSide，行号即 ps1 内行号）。
  3. 补充实测：**即使按 UTF-8 正确解码（BOM 为单个 U+FEFF），`param()` 依然失去首条语句位置**，
     同样报错 —— 所以「带 BOM」对 `irm | iex` 是致命的，与解码方式无关。
- 反向坑（实测）：若 ps1 无 BOM 但含中文，`powershell -File` 时 PS 5.1 按 GBK 读取，多字节序列会吞掉换行，
  注释吃掉后面的代码 → 报「表达式或语句中包含意外的标记 }」。
- **结论：`install-cli.ps1` 必须「纯 ASCII + 无 BOM」**（BOM 破坏 iex，中文破坏 -File）。
  因此 ps1 注释与输出全部改为英文，**中文提示统一交给 `install-cli.mjs` 输出**（Node 按 UTF-8 读，不乱码）。
- 顺带修掉两个退出码 bug：
  1. 函数里设 `$ErrorActionPreference='Stop'` → 原生命令（node）写 stderr 会抛终止错误，
     `return $LASTEXITCODE` 根本没执行。改为不设全局 Stop（需要中断处单独带 `-ErrorAction Stop`）。
  2. `& node ...` 的 stdout 会混入函数返回值，`$exitCode` 变成「输出+退出码」数组 → `exit` 报 0。
     改为 `& node ... | Out-Host`（winget 同理），退出码正常。
     注意不要用 `2>&1` 合并，否则 stderr 变成 ErrorRecord，控制台多出 CategoryInfo 噪音。
- 另：`irm | iex` 场景下不能用 `exit`（会关掉用户终端），已改为 `if ($PSCommandPath) { exit $exitCode }`。
- 验证：ps1 纯 ASCII（非 ASCII 字节 0）、无 BOM（head=23 20 6f）、latin1 与 UTF-8 两种解码均可解析；
  文件模式 `-File` 端到端跑通（第一源命中自有站下载 mjs），版本不匹配与 npm 缺失均正确返回 exit 1。
